Open live demo ↗ Full Stack Developer · 2024
01 — The problem

A charity needs to receive aid requests, check the documents, track donors and keep an audit trail of every case, with different permissions for each role.

02 — The solution

A PHP and MySQL portal: aid request submissions, document uploads, role-based access for staff and admins, donor tracking, and case auditing.

04 — Challenges & fixes
CHALLENGE

Charity cases and donor records are sensitive — hiding buttons in the UI is not real permission control.

FIX

Role-based access control enforced on every server-side script, not just in the front end, so permissions hold even for direct API calls.

CHALLENGE

Uploaded case documents are a classic attack surface — file type, size and storage all needed locking down.

FIX

Server-side validation of type and size, plus renamed storage paths so original filenames are never exposed to clients.

CHALLENGE

The charity needs to prove how every case was handled, and a single editable row can't tell that story.

FIX

A database-backed audit log records every create and update, and admins review the full case history instead of trusting one row.
